# 배포 구조

## 전체 그림

```
로컬에서 수정
     │  git push
     ▼
GitHub 저장소 (hyundae313/me, main 브랜치)
     │  푸시를 감지해 자동 실행
     ▼
GitHub Actions (.github/workflows/deploy.yml)
     │  npm ci → npm run build → dist/
     ▼
GitHub Pages
     │
     ▼
https://ryankim.kr/
```

직접 빌드해서 올리는 과정이 없습니다. `main` 에 푸시하는 것이 곧 배포입니다.

## 각 조각이 하는 일

### `.github/workflows/deploy.yml`

푸시될 때마다 GitHub 서버에서 도는 배포 절차입니다.

1. 저장소를 내려받고 Node 22 준비
2. `npm ci` — `package-lock.json` 에 적힌 버전 그대로 설치
3. `npm run build` — `dist/` 생성
4. `dist/index.html` 을 `404.html` 로 복사 (아래 "SPA 폴백" 참고)
5. `dist/` 를 Pages 에 배포

빌드가 실패하면 배포 단계로 넘어가지 않습니다. **사이트는 이전 버전이 그대로 유지됩니다.**

### `vite.config.js` 의 `base`

사이트가 어느 경로에 놓이는지 알려주는 값입니다. 지금은 도메인 루트라 `'/'` 입니다.

이 값이 틀리면 화면이 비어 보입니다. 브라우저가 엉뚱한 경로에서 `assets/` 를
찾기 때문입니다. 코드 안의 이미지 주소와 라우터는 모두 이 값을 기준으로 만들어지므로
(`import.meta.env.BASE_URL`), 경로를 옮길 일이 생기면 이 한 줄만 바꾸면 됩니다.

| 어디에 올리나 | `base` |
|---|---|
| `ryankim.kr/` (지금) | `'/'` |
| `hyundae313.github.io/me/` | `'/me/'` |

### `public/CNAME`

커스텀 도메인(`ryankim.kr`)을 기억시키는 파일입니다. 빌드 결과에 그대로 복사되어
Pages 에 전달됩니다. 도메인을 바꾸면 이 파일과 저장소 Settings → Pages 의
Custom domain 을 함께 고쳐야 합니다.

### SPA 폴백 (`404.html`)

이 사이트는 페이지가 `index.html` 하나뿐이고, `/dev` 같은 주소는 브라우저 안에서
자바스크립트가 처리합니다. 그래서 `/dev` 를 직접 열거나 새로고침하면 서버에는
`dev` 라는 파일이 없어 404 가 납니다.

`index.html` 을 `404.html` 로도 복사해두면, 없는 주소에 대해 GitHub Pages 가
이 파일을 돌려주고 앱이 정상적으로 뜹니다. 화면은 제대로 나오지만 **HTTP 상태
코드 자체는 404** 입니다. Pages 의 구조상 피할 수 없고, 사용자 입장에서는 차이가 없습니다.

## 저장소에 올라가지 않는 것

`.gitignore` 에 걸려 있습니다.

| 항목 | 이유 |
|---|---|
| `node_modules/` | `npm install` 로 언제든 다시 만들어짐 |
| `dist/` | 배포할 때 서버가 새로 만듦 |
| `logs/*.jsonl` | 방문 기록. 공개되면 안 됨 |
| `.env` | 로컬 설정 |

## 방문 추적 (현재 꺼져 있음)

`src/lib/analytics.js` 는 `VITE_TRACK_ENDPOINT` 가 비어 있으면 아무것도 밖으로
보내지 않고 브라우저 `localStorage` 에만 쌓습니다 (`?track=1` 을 붙이면 확인 패널이 뜹니다).
지금 배포본에는 이 값이 없어 **꺼진 상태**입니다.

켜려면 로그를 받아줄 서버가 따로 필요합니다. `server/collect.js` 가 그 수집기인데,
GitHub Pages 는 정적 호스팅이라 이 서버를 돌릴 수 없습니다.

```
브라우저 → POST https://수집기주소/collect → logs/YYYY-MM-DD.jsonl
```

켜는 순서:

1. 수집기를 어딘가에 띄웁니다 (Fly.io, Railway, 집 서버 등).
   그 서버에 `ALLOW_ORIGIN=https://ryankim.kr` 을 지정해야 브라우저가 요청을 보냅니다.
2. 저장소 Settings → Secrets and variables → Actions → New repository secret
   - 이름: `VITE_TRACK_ENDPOINT`
   - 값: `https://수집기주소/collect`
3. 다음 배포부터 적용됩니다. 워크플로에는 이미 연결해 뒀습니다.

로컬에서는 수집기를 같이 띄워 확인할 수 있습니다.

```bash
npm run build && npm run serve    # → http://localhost:8080
npm run report                    # 쌓인 로그 집계
```

## 저장소 설정 (한 번만)

- Settings → Pages → Source: **GitHub Actions**
  (`Deploy from a branch` 로 되어 있으면 빌드 결과가 아니라 소스가 그대로 올라갑니다)
- Settings → Pages → Custom domain: `ryankim.kr`, **Enforce HTTPS** 체크
