# 수정하고 배포하기

수정 → 확인 → 커밋 → 푸시. 푸시 이후는 전부 자동입니다.

## 1. 고치면서 확인하기

```bash
npm run dev
```

터미널에 뜨는 주소(<http://localhost:5173>)를 브라우저에서 엽니다.
파일을 저장하면 새로고침 없이 바로 반영됩니다. 확인이 끝나면 터미널에서 `Ctrl+C`.

같은 와이파이의 휴대폰에서도 볼 수 있습니다. 터미널에 함께 표시되는
`Network:` 주소를 폰 브라우저에 입력하세요.

## 2. 어디를 고치면 되나

| 고치고 싶은 것 | 파일 |
|---|---|
| 개인 페이지(`/`)의 글·목록 | `src/data/personal.js` |
| 개발자 페이지(`/dev`)의 경력·프로젝트 | `src/data/profile.js` |
| 사진 | `public/images/` 안의 파일을 **같은 이름으로** 교체 |
| 브라우저 탭 제목, 공유 미리보기 | `index.html` |

내용만 바꾸는 일이라면 대부분 위의 두 데이터 파일로 끝납니다.
사진은 파일명을 그대로 유지하면 코드를 건드릴 필요가 없습니다.

## 3. 뭘 고쳤는지 보기

```bash
git status     # 바뀐 파일 목록
git diff       # 실제로 바뀐 내용
```

## 4. 커밋하고 올리기

```bash
git add -A
git commit -m "인사말 수정"
git push
```

`-m` 뒤의 메모는 나중에 되돌릴 때 찾는 단서가 되므로 짧게라도 적어두는 편이 좋습니다.

## 5. 반영 확인

푸시하면 GitHub Actions 가 서버에서 빌드해 사이트에 올립니다. **1~2분** 걸립니다.

- 진행 상황: <https://github.com/hyundae313/me/actions>
- 초록 체크(✓)가 뜨면 완료
- 사이트: <https://ryankim.kr/>

로컬에서 `npm run build` 를 할 필요는 없습니다. 빌드 결과인 `dist/` 폴더는
커밋하지 않습니다 (`.gitignore` 에 들어 있습니다).

## 잘 안 될 때

**바뀐 게 안 보입니다**
브라우저 캐시입니다. `Cmd+Shift+R` (강력 새로고침).
그래도 그대로면 Actions 에서 배포가 끝났는지 확인하세요.

**Actions 에 빨간 X 가 떴습니다**
빌드가 실패한 것이고, 이 경우 **사이트는 이전 버전 그대로 유지됩니다**.
실패한 실행을 클릭하면 어느 줄에서 멈췄는지 나옵니다.
푸시 전에 `npm run lint` 로 미리 걸러낼 수 있습니다.

**잘못 올렸습니다**
```bash
git revert HEAD
git push
```
직전 커밋을 되돌리는 커밋이 새로 생기고, 이전 상태가 다시 배포됩니다.

**푸시하다 `HTTP 400` 이 납니다**
```bash
git config --global http.version HTTP/1.1
```
한 번만 설정해두면 됩니다.
